Dasar Version Control

Alur 4 Tahap Git

Ikuti empat tahap ini setiap kali kamu menyimpan perubahan kode.

01

Working Directory

Tempat kamu membuat dan mengedit file secara langsung di komputermu.

Perintah utama
git status
→
02

Staging Area

Area persiapan tempat kamu memilih perubahan yang siap untuk di-commit.

Perintah utama
git add .
→
03

Local Repository

Riwayat commit tersimpan di repositori lokal dalam direktori .git proyekmu.

Perintah utama
git commit -m "pesan"
→
04

Remote Repository

Kode dikirim ke server seperti GitHub agar bisa diakses dan dikolaborasikan tim.

Perintah utama
git push
→

Kesalahan Umum Pemula

Hindari jebakan ini agar alur kerja Git-mu tetap bersih dan aman.

⚠

Lupa git pull Sebelum Push

Langsung git push tanpa sinkronisasi dulu bisa memicu conflict atau penolakan dari remote. Biasakan git pull --rebase sebelum mulai bekerja.

✏

Pesan Commit Terlalu Samar

Menulis git commit -m "fix" atau "update" menyulitkan kolaborasi dan code review. Gunakan pesan yang deskriptif, misalnya "fix: validasi input email pada form login".

⎇

Tidak Mengecek Branch Aktif

Commit ke main secara langsung tanpa sadar bisa merusak kode produksi. Selalu jalankan git branch atau git status untuk memastikan kamu berada di branch yang benar.

📋 Rangkuman Alur Belajar Git

1

Mulai dengan git init atau git clone untuk menyiapkan repositori.

2

Edit file di Working Directory, lalu cek status dengan git status.

3

Pindahkan perubahan ke Staging Area menggunakan git add ..

4

Simpan snapshot dengan Local Repository via git commit -m "pesan jelas".

5

Bagikan ke tim lewat Remote Repository dengan git push.

6

Selalu git pull untuk mendapat pembaruan terbaru dari rekan kerja.

💡

Konsistensi adalah kunci – latih alur ini setiap hari dan Git akan terasa alami dalam waktu singkat.
